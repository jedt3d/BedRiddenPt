# BedRiddenPt: Bedridden Patient Locator (prototype)

A Flutter (Cupertino) prototype for volunteers in **Khlong San district, Bangkok**, who register elderly patients' home locations and care levels. It runs in the iOS Simulator. All data is on the device (SQLite); nothing is sent to a server. All sample patients are fictitious.

**Status (2026-11-19):** build issues #1–#28 are merged on `main`. See [docs/STATUS.md](docs/STATUS.md).

## What it does

- **Launch:** a one-time "Your name" screen, then the PIN (fixed at `000000`) on every launch. The ⋮ menu on the PIN screen resets the sample data and keeps the name.
- **List:** photo, name, age, subdistrict, care-level badge and status; search by name or national ID; filters; **Show inactive**. Swipe left to mark a patient deceased, or swipe a deceased row to restore it.
- **Map:** OpenStreetMap tiles, the district outline, pins colored by care level (bedridden red, homebound orange, social green, inactive grey), a legend with counts, and pin → name → Detail.
- **Detail:** all fields, dates in the Buddhist era, a mini map, and **Call**, **Navigate** (Apple Maps) and **Edit**.
- **Add / Edit:** prefilled from an unused sample patient. It has an ADL stepper (care level derived from it), birth year in B.E., national ID format and checksum checks, a duplicate-ID block, **Use my location** (±m, sets the subdistrict), and a photo from camera or library.

There's no delete: patients become inactive (moved or deceased) instead. Spec: [SPEC.md](SPEC.md). Terms: [GLOSSARY.md](GLOSSARY.md). Design: the [Figma prototype](https://www.figma.com/design/zHNLIMNEn1XPcNwBTZGw7B).

## Run it

Requirements: Flutter 3.47.9 (Dart 3.13.7), Xcode with an iOS Simulator, and internet access for map tiles.

```bash
flutter pub get
```

```bash
open -a Simulator
```

```bash
flutter run
```

PIN: `000000`. To test **Use my location**, set the Simulator's location to the district centre, then tap the button in the Add form:

```bash
xcrun simctl location booted set 13.7228,100.5023
```

## Develop

```bash
flutter analyze
```

```bash
flutter test
```

```bash
tool/check_tokens.sh
```

- **Design tokens:** every colour, spacing, radius and text style comes from `lib/theme/tokens.dart`, which is generated from `design/tokens.json` (`dart run tool/gen_tokens.dart`). `tool/check_tokens.sh` rejects raw values and Material imports in `lib/`.
- **Hooks:** enable the pre-commit check once per clone with `git config core.hooksPath tool/hooks`.
- **CI:** GitHub Actions runs analyze, tests and the token check on every PR and on `main`. `main` is protected: a PR must pass CI and be up to date with `main`.
- **Layout:** `lib/app/` (shell, routes, `AppScope`), `lib/data/` (database, `PatientRepository`), `lib/features/<area>/` (one folder per screen area; see [lib/features/README.md](lib/features/README.md)), `lib/shared/` (labels, national ID, map config, care style, avatar, badge), `lib/geo/` (point-in-area and nearest-road helpers), `lib/theme/` (generated tokens).

## Data and geography

- `assets/bootstrap.json`: 50 fictitious patients (the sample pool), generated by `data/gen_bootstrap.dart`. See [data/README.md](data/README.md).
- `data/schema.sql`: the app's SQLite schema.
- `assets/geo/`: the district and subdistrict boundaries, water and road names from OpenStreetMap (© OpenStreetMap contributors, ODbL). See [assets/geo/README.md](assets/geo/README.md).
- `spikes/map_geo/`: the map spike that proved `flutter_map`, OSM tiles and Simulator location before the build.
